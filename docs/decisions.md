## ADR-001: 技術スタック選定

**日付**: 2025-01-19  
**ステータス**: 採用

### 背景

政治家ダッシュボードMVPの実装において、開発速度、保守性、拡張性を考慮した技術スタックの選定が必要。

### 決定内容

- **フロントエンド**: Next.js (App Router) + TypeScript + Tailwind CSS
- **バックエンド**: Next.js Route Handlers
- **データベース**: Supabase (PostgreSQL + pgvector)
- **AI**: OpenAI API (text-embedding-3-large, Responses API)
- **テスト**: Vitest + React Testing Library + Playwright

### 理由

- Next.js App Routerは最新のReact機能をサポート、SSRとクライアントサイドの最適化
- TypeScriptで型安全性を確保
- Supabaseによりpostgres + pgvectorを簡単に利用可能
- OpenAI APIは安定性と性能に優れる
- Vitestは高速なテスト実行環境

### 結果

MVP開発の高速化と保守性の向上を実現。

## ADR-002: アーキテクチャパターン（ポート&アダプタ）

**日付**: 2025-01-19  
**ステータス**: 採用

### 背景

外部依存（データベース、AI API）の切り替えとテスタビリティを確保する設計が必要。

### 決定内容

ポート&アダプタ（ヘキサゴナル）パターンを採用：

- `/src/ports/`: インターフェース定義
- `/src/adapters/inmemory/`: テスト・開発用実装
- `/src/adapters/supabase/`: 本番用実装

### 理由

- 外部依存の抽象化によりテストが容易
- InMemoryとSupabase実装を環境変数で切り替え可能
- 将来の技術変更に対する柔軟性

### 結果

テストファーストでの開発が可能になり、外部サービス依存を最小化。

## ADR-003: RAG（Retrieval-Augmented Generation）の厳格モード

**日付**: 2025-08-19  
**ステータス**: 採用

### 背景

政治家の発言に関する情報提供において、情報の正確性と透明性が最重要。

### 決定内容

RAGチャットは厳格モードで実装：

- 必ず出典URL付きで回答、または「情報がありません」を返す
- 推測や一般論での回答を禁止
- システムプロンプトで引用逸脱を防止

### 理由

- 政治情報の透明性と信頼性確保
- ユーザーが情報源を確認可能
- 誤情報や推測の拡散防止

### 結果

信頼性の高い情報提供システムを実現。

## ADR-004: Instagram API の2段構えフォールバック

**日付**: 2025-08-22  
**ステータス**: 採用

### 背景

Instagram Basic Display APIの廃止により、SNS投稿取得の信頼性確保が必要。

### 決定内容

2段階フォールバック実装：

1. 第1選択: Graph API (Business/Creator アカウント)
2. フォールバック: oEmbed API

### 理由

- Basic Display API廃止への対応
- Graph APIはBusiness/Creatorアカウントでのみ利用可能
- oEmbedは個別投稿URLでの取得に対応

### 結果

Instagram投稿取得の安定性を向上。

## ADR-005: セキュリティファースト設計

**日付**: 2025-08-27  
**ステータス**: 採用

### 背景

APIキーや機密情報の露出リスクを最小化する必要。

### 決定内容

- 全APIキーはサーバーサイドのみで使用
- クライアント露出検知システム実装
- セキュリティミドルウェアで防御的ヘッダー設定

### 理由

- 機密情報の漏洩防止

- API濫用防止

### 結果

セキュアなシステム基盤を構築。

## ADR-006: TDD（テストファースト開発）原則

**日付**: 2025-01-19  
**ステータス**: 採用

### 背景

品質保証と保守性確保のため、テスト戦略の明確化が必要。

### 決定内容

全機能でTDD原則を適用：

1. 先に失敗するテストを作成
2. テストを通すための最小実装
3. リファクタリング

### 理由

- バグの早期発見
- リファクタリング時の安全性
- 仕様の明文化

### 結果

高品質なコードベースの維持を実現。200+のテストケースで安定性を確保。

## ADR-007: 日本語テキスト処理の最適化

**日付**: 2025-08-20  
**ステータス**: 採用

### 背景

議会発言のテキスト処理において、日本語特有の処理が必要。

### 決定内容

- チャンク分割: 「。！？…」での文単位分割
- クラスタラベル生成: 日本語ストップワードフィルタ
- K-Meansクラスタリング: k=6, 固定シード42

### 理由

- 日本語文章構造に適した分割
- 意味のあるクラスタラベル生成
- 結果の再現性確保

### 結果

日本語議会録の効果的な分析・可視化を実現。
